# Online Experiments and A/B Testing: labs

Hands-on notebooks for the SDAIA Academy course **DS-302 Online Experiments and A/B Testing**. Every lab works on
**Sufrah (سفرة)**, a fictional Saudi food-delivery marketplace with customers in six cities, restaurants, couriers,
an AI-ranked search and **Luqma (لُقمة)**, an in-app chat assistant. All the data is synthetic and generated by
`sufrah.py`; none of it describes real people.

**No model, no key.** The labs analyse experiment logs and simulations. Nothing calls a model and nothing is
downloaded at run time, so a laptop CPU or a Colab CPU runtime is enough and no account is needed.

## Quick start

**Google Colab.** Open a notebook from the table below. Its first cell clones this repository and installs
`requirements-colab.txt`.

**Local**, with [uv](https://docs.astral.sh/uv/):
```bash
git clone https://github.com/SDAIAAcademy/online-experiments
cd online-experiments/labs
uv sync                        # creates .venv from pyproject.toml; uv.lock pins every version
uv run jupyter lab
```
Run `00_setup_check.ipynb` once before Day 1. On Windows, if the path of the clone is long, keep the environment
on a short path: `set UV_PROJECT_ENVIRONMENT=C:\uvenv` before `uv sync`.

## Before and after the course

- **Pre-work (two hours).** Revise power and the two-sample test: what alpha and power mean, the standard error
  of a difference in means, and the sample-size formula that Day 1 Session 4 starts from. DS-201 and DS-205 cover
  the ground. Then take the entry quiz: the Day 1 questions on the practice page of the course site, without an
  assistant. Run `00_setup_check.ipynb` at the end.
- **Follow-up (tracked).** Within the period your trainer sets, review one experiment from your workplace, or a
  public write-up, against the review board's checklist of Lab 4.4, and submit the one-page review.

Each lab starts from a **supplied reference state**: whatever it needs from an earlier lab is either given in the
notebook or read from `data/reference/`, so none depends on finishing another. Every exercise has a safety net: if
your function is not written yet, the notebook says so, uses the reference result and carries on, so the cells after
it still run. Solutions are in `solutions/`.

## The data

| Source | What it is | Used in |
|---|---|---|
| `sufrah.stream()` | 28 days of T-101 (AI-ranked search): assignments, searches, sessions, orders, with 28 pre-period days | Days 1 and 2, Lab 4.3 |
| `sufrah.peek_sim()` | daily monitoring of a test with or without a true effect | Labs 3.1 and 3.2 |
| `sufrah.dispatch_sim()` | a marketplace in which couriers are shared between arms | Labs 3.3 and 3.4 |

| `sufrah.capstone_data()` | the three capstone changes | Lab 4.4, capstone |
| `data/tests_registry.json`, `srm_tests.csv` | Sufrah's test registry and the daily assignment log of three tests | Lab 1.2 |
| `data/data_inventory.csv` | event fields with their classification, for the purpose-limitation decision | Lab 1.3 |
| `data/preregistration_T101.json` | T-101's pre-registration: guardrail limits and the decision rule | Lab 4.3 |
| `data/segments_T205.csv` | twenty segment results of T-205 (menu photos) | Lab 4.2 |
| `data/writeups/` | five write-ups for the review board, W1 to W5 | Lab 4.4 |
| `data/capstone_changes.json` | the three capstone changes | Lab 4.4, capstone |

`prepare_data.py` rebuilds the files in `data/` (they are committed). The simulator plants known problems for the
labs to find: a sample ratio mismatch in one app build, dilution from customers who never searched, heavy-tailed
order values, interference through shared couriers, a novelty effect and a harm in Luqma, false segment wins, and one
seeded fault in each of four write-ups.

## Modes

- **Full** (the default) uses 200,000 customers and runs each lab in under a minute or two on a laptop.
- **Quick**: `SUFRAH_QUICK=1` uses 30,000 customers and fewer simulations, for a fast check. A few quick-mode
  numbers differ from the slides, which quote full mode; Lab 4.3 always uses the full stream.
- `SUFRAH_STRICT=1` turns every check into an error, for testing the solutions.

## Capstone

`capstone/README.md` describes the pack and the defence; `capstone/starter.py` generates the data for one change.

The notebooks are generated from the percent-format sources in `labs/_src/` by `labs/_tools/py2nb.py` (`uv run python _tools/py2nb.py` from `labs/`), which also writes the solutions to `labs/solutions/`. Edit the sources, not the notebooks.
